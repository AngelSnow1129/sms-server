接口文档

两个核心接口 + 一个通道回调。所有接口均为 POST；4xx 错误为纯文本，成功为 JSON。

token 计算方式

取码接口的 token 是收件人号码的 HMAC 摘要，调用方与服务端共享 HMAC_SECRET 即可对账，服务端不需要保存明文手机号作索引：

token = hex( HMAC-SHA256( key = HMAC_SECRET, message = 收件人手机号 ) )
  • 消息体就是手机号字符串本身（建议带国家码，如 +8613900000000），不做其他预处理
  • 输出为小写十六进制（64 字符）
  • 可用首页取码助手在浏览器本地计算，或用命令行： 
    python3 -c "import hmac,hashlib;print(hmac.new(b'你的HMAC_SECRET',b'+8613900000000',hashlib.sha256).hexdigest())"

1. 短信回调

POST /api/v1/webhook/sms/{WEBHOOK_SECRET}

路径最后一段即 WEBHOOK_SECRET，服务端用常量时间比较校验，防时序侧信道。校验通过立即返回 200，业务异步处理。

请求体（JSON，上限 64 KiB）

字段必填说明
provider否供应商标识，如 twilio；仅用于落库记录
sender否发送方号码
recipient是接收方号码，缓存 key 的计算依据
body是短信原文，服务端从中提取验证码

响应

状态码响应体场景
200{"status":"ok"}校验通过，已投递后台处理
401unauthorized（纯文本）token 为空、不匹配或路径含多余层级
400invalid json（纯文本）请求体不是合法 JSON 或超过 64 KiB
405method not allowed（纯文本）非 POST

验证码提取规则

正则 \b(\d{4,8})\b 取第一个匹配的 4-8 位数字。这是通用启发式：短信中先于验证码出现的 4-8 位数字（订单号、金额等）可能被误提。同号新码直接覆盖旧码，旧码立即失效。需要更精准的提取时，用下面的 SMSForward 通道 + 模板机制。

2. 查询验证码

POST /api/v1/otp
{"token": "<按上文算法计算的 HMAC 十六进制>"}

token 会先做首尾空白裁剪；为空返回 400 missing token。

响应

响应体说明
{"status":"success","code":"123456"}命中；该码立即失效（阅后即焚）
{"status":"pending"}未命中：未收到短信、已过期、已被取走或 key 不匹配（也是 200）
未命中也返回 200：调用方按 status 字段轮询即可，无需按状态码分支。同一验证码不会被取走两次；重试同一次查询不会重复得到结果。

3. SMSForward 通道回调

POST /api/v1/webhook/smsforward/{channel_id}/{token}

为安卓转发工具（如 SmsForwarder）提供的多通道入口：每个通道独立 webhook_secret，可绑定提取模板与来源白名单，避免所有设备共享同一密钥。

请求体在短信回调字段基础上多一个 source（设备/来源标识，配置了 source_whitelist 时必填且必须命中）。

该接口随上游 PR #1（smsforward 通道 + 模板提取）提供，当前开发分支尚未合入；可用性与配置格式以合并后的仓库文档为准。应用侧配置步骤见 SMSForward 对接教程。

部署形态与配置

项Cloudflare 一键部署自托管（Docker / 二进制）
入口部署按钮（向导填两个密钥）docker build 或 go build，环境变量注入
验证码存储D1（唯一事实源，自动建表）DB_DRIVER=mysql（默认，内存缓存）或 DB_DRIVER=sqlite（SQLITE_PATH 持久化）
公共必填HMAC_SECRET、WEBHOOK_SECRET（openssl rand -hex 32 生成）
有效期OTP_TTL_SECONDS（秒，默认 300）OTP_CACHE_TTL_MINUTES（分钟，默认 5）
清理周期Cron 每 30 分钟（固定）CLEANUP_INTERVAL_SECONDS（秒，默认 30）
监听地址由 Workers 分配SERVER_ADDR（默认 :53340）

自托管启动前两个密钥必填，为空立即退出；完整变量清单见仓库 .env.example 与 README。

通用限制

  • 请求体上限 64 KiB，超出返回 400
  • HTTP 超时：读 5s、写 5s、空闲 120s（自托管）
  • 异步接口返回 200 不代表短信已入库，写库失败仅记录服务端日志
  • 日志不包含验证码明文、完整 token 与手机号明文，仅记录 recipient_hash 前 8 位

常见问题

取码一直 pending？

按顺序排查：token 是否用同一 HMAC_SECRET 和完全相同的号码字符串计算（空格、大小写、有无 +86 都会导致不一致）；验证码是否已过期或已被取走（阅后即焚，第二次查必 pending）。

网页算出的 token 与服务端不一致？

用首页助手生成的 python3 对照命令在部署机上再算一次：两者一致说明服务正常，问题出在调用方密钥/号码；不一致说明服务端密钥与浏览器里填的不同。

模拟短信返回 401？

WEBHOOK_SECRET 作为路径最后一段传输，注意 URL 编码与多余层级（.../sms/密钥/extra 会按 401 拒绝）。
